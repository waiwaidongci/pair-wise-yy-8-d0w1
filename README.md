# 古法纸浆发酵批次管理

一批原料同时照看几口缸的记录页：每缸记水位、温度和上次换水时间；异常时整批暂停换水，其他缸仍可追加观察。

运行：

```bash
npm start
```

访问 `http://localhost:3039`。数据保存在 `data/paper-pulp-fermentation.json`（旧的“一口缸一条”数据首次启动时自动迁移成批次）。

## 业务规则

- **一批多缸**：建档时一次登记多口缸，每缸单独记录水位（%）、温度、上次换水时间。
- **缸位唯一**：同一口缸不能留在两个未结束批次；批次结束（或状态改为“已结束”）后缸位释放，可进入新批次。
- **换水间隔**：距上次换水不足 24 小时（`MIN_WATER_CHANGE_HOURS`，见 `batch.js`）的换水申请不执行，停在“待处理”，到点后可重试。
- **整批暂停换水**：某口缸出现霉点或水位低于 30%（`LOW_WATER_LEVEL`）时，整批暂停换水、批次转入“异常观察”；暂停期间其他缸的观察照常追加。异常全部解除后可手动恢复换水。

## 文件划分

| 文件 | 职责 |
| --- | --- |
| `batch.js` | 批次判定：建档、缸位冲突、每缸观察、换水间隔与待处理、异常暂停/恢复、统计 |
| `store.js` | 文件存储：JSON 读写、旧数据迁移 |
| `page.js` | 页面操作：建档表单（多缸编辑）、每缸观察/换水、批次卡片、筛选、统计 |
| `server.js` | HTTP 路由，只负责把请求转给 `batch.js` 并用 `store.js` 落盘 |

原有接口 `/api/items`（列表/建档/PATCH/备注/每日 action）和 `/api/stats` 继续可用；新增批次接口见 `server.js`（`/api/batches`、`/vats/observation`、`/vats/water-change`、`/vats/retry`、`/resume`、`/finish`）。
